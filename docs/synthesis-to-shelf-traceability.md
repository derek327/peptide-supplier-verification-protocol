# Traceability from Synthesis to Shelf: Record Linkage Across Five Handover Boundaries

*A documentation note for buyers auditing whether a batch record actually connects a vial to a synthesis run.*

**Scope.** "Traceability" is claimed on almost every supplier page and demonstrated on almost none. What a buyer needs is narrower and more mechanical than the word suggests: for one specific vial, can the supplier produce a chain of records in which every hop is bound by an identifier that survives the hop, and in which the quantities and dates on either side of each hop reconcile? That question can be answered with arithmetic on the documents themselves, without visiting a facility and without any analytical instrument. This note sets out the five record sets that make up the chain, the identifier rules that decide whether the chain exists at all, the mass and date arithmetic that tests it, and the failure modes that show up repeatedly in document review. It is a procurement documentation note: it contains no handling instructions, no storage guidance and no biological claims.

---

## 1. What the batch record is actually asserting

A batch record asserts an identity claim of the form *this vial contains the material produced by synthesis run X, released by QC record Y, filled under packaging record Z, and delivered on shipment record W*. Four independent claims, each with a different author, each with its own failure mode.

The instructive part is that the claims are only joined by identifiers. Chemistry does not join them: two vials from different runs are chemically indistinguishable once they are lyophilised powder in identical packaging. The join is documentary, which means traceability is a property of the paperwork, and paperwork can be complete, incomplete, or internally contradictory. A buyer can test all three conditions from the documents alone.

## 2. The identifier decides whether a chain exists

Most suppliers issue an internal lot number such as `BPC2409A`. That string is usually unique inside one supplier's system, is frequently reused across product lines, is sometimes reissued after a re-work, and encodes nothing a buyer can verify. Three properties are needed before an identifier can carry a chain.

**Unique within the supplier, permanently.** Re-use after a period — a common legacy-ERP behaviour when the sequence wraps — destroys the link retroactively. A buyer cannot detect this from a single record; it surfaces when two CoAs years apart carry the same lot string with different dates.

**Structured and checkable.** If the identifier encodes manufacturing site, year-month of synthesis, and a sequence, then a transcription error becomes detectable rather than silently plausible. A check character makes the difference between "this string looks like a lot number" and "this string is a well-formed lot number". The scheme used in the accompanying dataset is:

```
HLX-OEM-2604-A7-W
 │    │    │   │  └── check character (base 36, position-weighted sum)
 │    │    │   └───── sequence, base 36 (A7 = 367)
 │    │    └───────── year and month of synthesis (YYMM)
 │    └────────────── manufacturing or filling site code
 └─────────────────── issuer code
```

The check character is computed over the hyphen-free payload as `sum(value(char_i) × (i+1)) mod 36`, mapped onto `0-9A-Z`. Any single-character transcription error changes the check, so a CoA lot number that fails its own checksum is a document-integrity finding, not a typing nuisance. One caveat belongs here: a check character proves the string was generated by the scheme, not that the material exists. It raises the cost of a fabricated lot number; it does not eliminate it.

**Immutable across re-work and splitting.** Two operations silently break chains. A re-purification that returns material to a new lot number orphans the original QC release — the buyer then holds a CoA for material that no longer exists under that identity. A split that issues child lot numbers without naming the parent orphans the synthesis record. Both are acceptable operations with a written rule: a re-worked lot keeps the parent identifier with a revision suffix (`...-F.R1`), and a split lot issues children that carry the parent identifier in a mandatory `parent_lot` field. Where no such rule is written, assume the links are lost.

## 3. Five record sets, and what reconciles across each boundary

| # | Record set | Author | What the next hop needs from it | Typical break |
|---|---|---|---|---|
| 1 | Synthesis and purification record | Production | Lot ID, crude mass, purified mass, purification method, date | Yields absent; mass reported only as "batch size" |
| 2 | QC release record (CoA) | QC | Lot ID, test methods, results, release date, approver | Same CoA reused across several lot numbers |
| 3 | Fill and packaging record | Fill suite | Lot ID, fill date, units, mass per unit, label version | Label version not linked to a document revision |
| 4 | Storage and custody ledger | Warehouse | Lot ID, location changes, temperature records, dates | Ledger exists per site, never consolidated |
| 5 | Shipment and receipt record | Logistics / buyer | Lot ID, dispatch date, carrier, quantity, receipt signature | Forwarder's waybill carries an order number, not a lot ID |

The boundary that fails most often is 4→5. Everything upstream of dispatch is inside the supplier's own quality system and tends to be consistent because one organisation owns it. At dispatch the identifier often degrades to an order or invoice number, and the receiving site has no way to prove that the carton it signed for is the carton whose CoA it holds. A supplier who can quote the lot ID on the commercial waybill has solved the boundary; most cannot.

Boundary 2→3 fails in a different way: the fill record is written by a department that treats the lot ID as a stock code rather than an identity. Where the fill record lists units and mass but not the release record number, a buyer cannot tell whether the units were filled before or after release.

## 4. Mass balance is the arithmetic spine

The chain has a quantity dimension, and it is the part a buyer can check without any help from the supplier beyond the numbers already on the records.

```
purification_yield = purified_mass / crude_mass
fill_yield         = filled_mass  / purified_mass
overall_yield      = filled_mass  / crude_mass
```

The governing rule is monotonicity: **recorded mass cannot increase along the chain.** Every hop either loses material — to purification losses, to sampling, to holdback for retention — or, at the extreme, transfers all of it. A hop that gains mass has exactly three explanations, and the buyer should demand which one applies:

1. **Unreported blending.** Material from a second synthesis run was added, and the lot identity quietly covers two runs. This is the serious case: the CoA then describes a mixture whose composition was never released as such.
2. **A different basis on either side.** Crude mass reported as purified peptide content on one record and as weighed salt on the next produces an apparent gain with no physical event behind it. This was the subject of an earlier note on purity versus content; the same denominator confusion reappears here as a mass-balance artefact.
3. **A transcription error.** Benign, but it invalidates the arithmetic until corrected, and a supplier who cannot correct it under revision control has a documentation problem regardless.

A worked example makes the tolerance question concrete. Crude 5.00 g, purified 3.80 g, filled 3.60 g gives purification yield 76.0 %, fill yield 94.7 %, overall 72.0 %. Losses of that size in a multi-step purification are ordinary. What is not ordinary is a claim of 98 % overall yield on a multi-step chromatographic purification: at that level, either the mass basis changed between records or the numbers were not measured.

## 5. Time: ordering and retention

Dates are the second arithmetic dimension, and they are cheaper to check than mass.

**Ordering.** The stage dates must be non-decreasing in the order synthesis → purification → QC release → fill → dispatch. Any inversion is a finding. The most common inversion is a QC release dated before the purification it releases; the second most common is a dispatch date before the fill date, which usually means the fill date was entered retrospectively.

**Retention.** Each record has a retention obligation expressed as a period after release or after expiry, and the supplier's specification should state the period rather than leave it implied. A retention deadline is simple arithmetic — `deadline = anchor_date + retention_months` — and the useful output for a buyer is not the deadline itself but which records are approaching it. A batch whose synthesis record falls out of retention while the released material is still in commerce cannot be traced by anyone, however good the record was when it was written. The dataset accompanying this note uses a 60-month example policy to make the arithmetic concrete; the period is a policy input, not a regulatory constant, and must be replaced with whatever the supplier's own specification states.

## 6. An audit a buyer can run on the documents

The five checks below reproduce the audit implemented in the accompanying `traceability_audit.py`, and each is expressible as a spreadsheet column formula.

1. **Identifier validity.** Every lot string on every document parses under the scheme and passes its check character, and the site code matches the site named on the document.
2. **Stage coverage.** All five record sets are present, and each stage's mandatory fields are non-empty. A stage present with an empty evidence field counts as absent — this is where "we have a traceability system" usually fails.
3. **Ordering.** Stage dates non-decreasing.
4. **Mass continuity.** Recorded mass non-increasing along the chain, within a stated tolerance.
5. **Retention horizon.** Every record's deadline computed, and any deadline inside the near-term horizon flagged.

A lot that passes all five is *documentarily complete*. That phrase is deliberately weaker than "authentic". These checks detect internal contradiction and omission, and they raise the cost of fabrication, but a consistently fabricated record set passes all five. Only analytical or physical verification addresses authenticity, and that is outside this note.

## 7. Failure modes worth recognising on sight

- **One CoA, several lot numbers.** The CoA states a lot range or names a product without a lot. It cannot release more than one lot.
- **Re-lotting without a parent.** Material is re-numbered on re-test. The new CoA is clean and the original release is unreachable.
- **Back-dated release.** Release dated the same day as purification, or on a date the QC instrument log will not corroborate.
- **Split lots without children.** Bulk material divided for several customers, each issued a fresh number with no parent reference.
- **Forwarder as the last link.** The waybill carries an order number only, so the receiving site cannot bind carton to CoA.
- **The word used in place of the thing.** "Full traceability" on a marketing page, with no lot-level record available on request. The test is one email: ask for the five record sets for one lot number. A supplier with a chain answers in a day; a supplier without one answers with a policy document.

## 8. What changes when a third party's name goes on the label

In an OEM or private-label arrangement the chain acquires a boundary that is contractual rather than physical. The manufacturing site still authors record sets 1–3, the buyer's brand appears on the label, and the buyer is the party who must produce the chain to *its* customers. Three things have to be specified in writing before that arrangement is auditable:

- **Which party holds which record**, and for how long after the relationship ends. A brand owner with no right to retain the synthesis record cannot trace its own product, and a manufacturing site that discards records on contract termination strands every batch in the field.
- **Whether the buyer's lot number is the maker's lot number or maps to it.** Two numbering systems joined by a written mapping is workable; two numbering systems joined by habit is not.
- **Who owns a re-work decision**, and how a revision is communicated to the brand owner after the label has been printed.

Each of these is a documentation clause, not a technical capability, and each is cheap to settle before the first batch and expensive to settle afterwards.

## 9. Buyer checklist

1. Ask for the five record sets for one named lot, not for a traceability policy.
2. Verify the lot identifier's structure and check character yourself; do not accept "internal code".
3. Reconcile mass across the chain, and demand an explanation for any hop that gains.
4. Check that stage dates are non-decreasing, and that release does not precede purification.
5. Ask what happens to the identifier on re-work and on split; require a parent field if splitting occurs.
6. Confirm the lot ID appears on the commercial shipping document, not only on the internal one.
7. Ask which records survive contract termination, in writing, before the OEM relationship starts.

## 10. Limits of this note

- The checks detect omission and internal contradiction. They do not establish authenticity, and a coherently fabricated record set passes all of them.
- The identifier scheme here is an example design, not a standard. Real suppliers use their own; the audit applies as long as the scheme is structured and checkable, and its checksum must be recomputed rather than assumed.
- The retention period used in the dataset is a policy input chosen to make the arithmetic visible. It is not a regulatory constant and carries no legal meaning.
- Mass yields quoted in examples are illustrative arithmetic, not benchmarks; purification performance varies with sequence, scale and method.
- Nothing here addresses handling, storage conditions, stability or any use of the material. It is a documentation review procedure.
